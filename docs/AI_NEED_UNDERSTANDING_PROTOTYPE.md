## 2. 原型目标

原型用于验证：模型能否从消费者的模糊购物表达出发，在简短多轮对话中逐步形成三层需求，并最终生成一张可确认、可修改、可供后续推荐能力使用的需求卡片。

原型不以验证通用聊天能力为目标。需要验证的核心机制是：

- 能否快速形成目标角色外轮廓。
- 能否发现消费者尚未表达的直接需求。
- 能否识别消费者对目标者理解中的高影响遗漏。
- 能否控制对话轮次并在适当时机停止。
- 能否在用户修正后保持需求状态一致。

## 3. 原型形态

原型采用一条真实可交互的窄纵切流程：

```text
模糊需求输入
    ↓
目标角色轮廓
    ↓
动态候选直接需求
    ↓
最高影响认知缺口
    ↓
需求卡片确认与修改
    ↓
完成需求理解
```

桌面端采用“对话 + 需求卡片”双区布局：

- 左侧负责对话、候选项和自由输入。
- 右侧逐步呈现需求卡片。
- 第二轮以后开始展示已有卡片内容。
- 用户可以随时编辑已经形成的需求。

移动端以对话为主视图，需求卡片通过顶部摘要或抽屉展开。

## 4. 原型边界

### 本原型实现

- 模糊自然语言输入。
- 简短多轮对话。
- 快捷候选项与自由文本回答。
- 三层需求状态的持续更新。
- 对话轮次、重复问题和停止条件控制。
- 需求卡片生成、编辑与确认。
- 当前会话的临时保存。

### 本原型不实现

- 商品搜索、推荐和排序。
- 选购方案、对比和购买清单。
- 实时价格、库存、优惠和购买链接。
- 用户账号和跨会话长期记忆。
- 完整消费者画像。
- 多模型协作或复杂智能体流程。

## 5. 三层需求在原型中的作用

### 5.1 第一层：目标角色轮廓

第一层回答三个问题：

1. 目标者是谁。
2. 消费者与目标者是什么关系。
3. 谁购买、付款、决定、接收和使用。

第一、第二轮优先建立该外轮廓。初始输入已经包含的信息直接进入状态，不重复询问。

目标身份只记录与购买有关的生活状态、场景角色和使用经验，不根据人口属性直接推断消费偏好。

### 5.2 第二层：购买决策需求

第二层从有限候选需求池中，选择当前最可能影响购买方向的内容：

- 使用结果。
- 预算与价值。
- 使用情境。
- 硬性限制。
- 功能与性能。
- 风格与感受。
- 学习、安装和维护成本。
- 品质与使用寿命。
- 售后与试错风险。
- 关系表达。
- 时间限制。
- 排除项。

每轮最多向用户呈现 3–4 个候选项，并固定保留“其他”和“不确定”。候选项只是待确认方向，不能直接写成用户已确认需求。

### 5.3 第三层：目标认知补全

第三层判断消费者对目标者的理解中，是否存在可能改变购买方向的遗漏、含混或未经验证判断。

优先关注：

- 实际行为与性格概括不一致。
- 不知道目标者当前使用什么或哪里不满意。
- 没有考虑明确排斥项。
- 没有考虑目标者的时间、空间、经验或使用能力。
- 消费者的判断主要来自自己的推测。
- 遗漏共同使用者或环境限制。

默认只追问一个最高影响认知缺口。只有上一个答案产生新的重大冲突时，才允许第二次第三层追问。

## 6. 对话状态与节奏

### 6.1 对话阶段

内部对话阶段包括：

```text
outline → direct_needs → cognition_gap → card_review → complete
```

- `outline`：形成目标角色轮廓。
- `direct_needs`：补充直接需求和优先级。
- `cognition_gap`：检查最高影响认知缺口。
- `card_review`：展示并修改需求卡片。
- `complete`：用户确认需求。

### 6.2 建议轮次

- 第 1–2 轮：目标角色外轮廓。
- 第 2–3 轮：候选直接需求。
- 第 3–4 轮：高影响认知缺口。
- 第 4–5 轮：主要冲突与卡片确认。

这不是固定脚本。信息已经存在时跳过对应问题；没有高影响认知缺口时提前进入卡片确认。

### 6.3 停止条件

满足以下条件时停止主动追问：

- 已形成目标身份、关系和主要角色组成。
- 已明确购买目标。
- 已获得预算或价格态度。
- 已获得主要使用场景。
- 已获得至少一个优先级或硬性限制。
- 不再存在值得占用一轮对话的高影响认知缺口。

第五次主动澄清后，即使仍有低影响未知信息，也先形成需求卡片。用户可以主动选择继续补充。

## 7. 问题选择机制

每轮只选择一个主题，优先级遵循：

> 提问价值 = 对后续选择的影响 × 当前不确定程度 × 消费者能够回答的概率 ÷ 回答成本

问题满足以下任一条件时，通常值得占用一轮对话：

- 不同答案会改变可能的品类方向。
- 不同答案会改变预算或价值取向。
- 答案可能产生新的硬性排除条件。
- 当前需求建立在未经确认的消费者推测上。

系统需要记录已问主题，避免以不同措辞重复询问。用户回答“不确定”后降低同类问题优先级，不继续施压。

## 8. 内部需求状态

应用维护一份不可见的结构化需求状态，而不是仅依赖完整对话文本。

```text
conversation
- phase
- turn_count
- asked_topics
- next_action

target_context
- identity
- relationship
- initiator
- buyer
- payer
- decision_maker
- recipient
- users
- co_users_or_influencers

direct_needs
- desired_outcome
- budget
- usage_context
- preferences
- hard_constraints
- exclusions
- priorities
- tradeoffs

target_understanding
- confirmed_information
- consumer_assumptions
- high_impact_unknowns
```

模型可以在内部为字段维护来源、确认状态、置信程度和更新轮次。这些信息仅用于选择下一问题、处理冲突和响应用户修正，不展示在用户卡片中。

## 9. 单轮处理结果

每次收到用户回答后，原型需要完成四件事：

1. 提取新增信息和用户修正。
2. 更新三层需求状态。
3. 判断是否还有值得追问的高影响缺口。
4. 返回下一个问题，或进入需求卡片确认。

建议的结构化结果形态：

```json
{
  "updated_state": {},
  "candidate_needs": [],
  "next_action": "ask",
  "question_topic": "usage_role",
  "question": "这件礼物主要由爸爸自己使用吗？",
  "answer_options": [
    "是，他自己用",
    "我们会一起用",
    "还不确定",
    "其他情况"
  ]
}
```

原型应用负责验证结构、限制轮次、过滤重复主题和渲染需求卡片。模型不能绕过应用的停止条件持续追问。

## 10. 用户可见需求卡片

```text
需求卡片

这次想解决什么
- 购买目标
- 使用或赠送场景

为谁购买
- 目标身份
- 消费者与目标者的关系
- 谁购买 / 谁决定 / 谁使用

已经明确的需求
- 预算与弹性
- 使用情境
- 重要偏好
- 硬性限制与排除项
- 优先级与必要取舍

还需要确认
- 可能影响选择、但目前无法确定的事项
```

卡片不展示需求形成说明、模型推理、信息来源、置信度或内部状态。

用户可以直接编辑、删除或补充字段。用户修改后，以最新值更新内部状态；只有修改导致核心信息缺失时才继续询问。

## 12. 关键交互规则

1. 每轮只处理一个主题。
2. 快捷候选项不超过四个，另加“其他”和“不确定”。
3. 用户已提供的信息不能重复询问。
4. 候选项必须是待确认方向，不能直接写成已确认需求。
5. 不根据年龄、性别、职业或家庭角色直接推断偏好。
6. 第三层优先询问实际行为、过去事件和排除项。
7. 用户选择“不确定”后，不用相同方式继续追问。
8. 达到停止条件后主动生成卡片。
9. 用户编辑卡片后，删除与新内容冲突的旧状态。
10. 卡片只展示需求内容，不展示模型内部形成过程。

## 13. 关键状态

| 状态 | 原型行为 |
| --- | --- |
| 初始信息很少 | 从目标者或场景中选择最高价值问题 |
| 初始信息充分 | 跳过已知的第一层或第二层问题 |
| 自用场景 | 自动合并消费者与目标者相关角色 |
| 多人使用 | 记录主要目标者和共同使用者 |
| 用户不确定 | 将必要信息保留为待确认项 |
| 信息相互冲突 | 用一次确认问题澄清 |
| 达到第五轮 | 先生成当前卡片，不继续低价值追问 |
| 用户修改卡片 | 使用新值更新内部状态 |
| 模型输出异常 | 保留已有内容，允许重新生成当前回复 |

## 14. 主演示路径

### 为他人购买

输入：

> 我想给刚退休的爸爸买件东西，预算大约 2000 元，但不知道买什么。

原型需要证明：

1. 不重复询问已经明确的关系和预算。
2. 能识别消费者是购买者和付款者，爸爸是接收者和使用者。
3. 能提出与当前角色和场景相关的候选直接需求。
4. 能用一个行为问题发现消费者认知中的遗漏。
5. 能在五轮以内形成需求卡片。
6. 用户修改卡片后，显示内容与内部状态一致。

### 自用场景

输入：

> 我想改善在家办公时腰酸的问题，但不知道应该买什么。

原型需要证明：

1. 自动识别消费者与目标者为同一人。
2. 合并购买、决策和使用角色，避免逐项询问。
3. 从实际使用行为中发现遗漏，不强行构造人物画像。

## 15. 原型完成标准

- 能从模糊表达开始完整走通需求理解流程。
- 能在 3–5 次用户回复内形成需求卡片。
- 不重复询问用户已经表达的信息。
- 候选直接需求与当前角色及场景相关。
- 至少能发现一项用户此前没有说明的重要信息。
- 能接受“不确定”并合理保留待确认项。
- 用户可以修改并确认需求卡片。
- 不依赖人口标签进行刻板推断。
- 不进入商品推荐、选购方案或交易流程。
