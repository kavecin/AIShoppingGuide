## 2. 本轮目标

让带着模糊购物意图的消费者，通过简短多轮对话形成一张可确认、可修改、可供后续推荐使用的需求卡片。

需求卡片需要回答三类问题：

1. 目标者是谁，消费者与目标者是什么关系，购买中有哪些角色。
2. 消费者对本次购买有哪些直接期待、约束和优先级。
3. 消费者对目标者的理解中，还有哪些会影响购买方向的遗漏或含混信息。

## 3. 功能边界

### 本轮负责

- 接收消费者的模糊购物表达。
- 在前两轮形成目标身份、双方关系和角色组成的外轮廓。
- 根据上下文提出少量候选直接需求。
- 识别一个或少数高影响的目标认知缺口。
- 形成并允许用户修改需求卡片。
- 将结构化需求交给后续推荐能力。

### 本轮不负责

- 生成单品类或多品类选购方案。
- 推荐具体品牌、型号或商品。
- 查询实时价格、库存、优惠和购买链接。
- 比价、下单和交易履约。
- 构建跨会话长期人物画像。

## 4. 用户与角色定义

### 消费者

发起本次购物需求并与 AI 对话的人。消费者可能是购买者、付款者或决策者，但不一定是实际使用者。

### 目标者

本次购买主要希望服务或影响的人。目标者可以是消费者本人、他人，也可以是一组共同使用者。

### 购买角色

| 角色 | 定义 |
| --- | --- |
| 发起者 | 提出购买需求的人 |
| 购买者 | 执行购买的人 |
| 付款者 | 承担费用的人 |
| 决策者 | 对最终选择有决定权的人 |
| 接收者 | 接收商品或礼物的人 |
| 使用者 | 实际使用商品的人 |
| 共同使用者或影响者 | 会共同使用或显著影响选择的人 |

同一个人可以承担多个角色。自用场景中，系统应自动合并已经明确重合的角色，不继续逐项询问。

## 5. 三层需求模型

### 5.1 第一层：目标角色轮廓

第一层的目标是在第一、第二轮对话中形成粗粒度外轮廓，而不是完成详细人物画像。

#### 目标身份

只记录与本次购买有关的信息：

- 自用、送人或共同使用。
- 与场景有关的生活阶段或当前状态。
- 与使用有关的职业、家庭或生活角色。
- 与目标品类有关的经验和能力水平。

年龄、性别等人口属性不能单独作为偏好推断依据。

#### 消费者与目标者的关系

- 双方是什么关系。
- 关系的熟悉程度和分寸。
- 消费者是否方便直接询问目标者。
- 本次购买是否承载礼物、纪念、感谢或其他关系表达。

#### 角色组成

系统需要知道谁购买、谁付款、谁决定、谁接收、谁使用，以及是否还有共同使用者。只询问尚不明确且会影响决策的角色。

### 5.2 第二层：购买决策需求

第二层关注消费者尚未完整提出、但能够直接改变购买方向的需求。

#### 候选需求池

| 类别 | 可能内容 | 使用条件 |
| --- | --- | --- |
| 使用结果 | 想解决的问题、希望发生的变化 | 每次都需要 |
| 预算与价值 | 上限、理想区间、弹性、低价或长期价值 | 每次都需要 |
| 使用情境 | 地点、频率、持续时间、单人或多人 | 影响选择时询问 |
| 硬性限制 | 空间、尺寸、兼容性、安全、过敏、材料 | 根据场景提出 |
| 功能与性能 | 必备能力、性能下限 | 已出现品类方向时使用 |
| 风格与感受 | 外观、颜色、触感、氛围、身份表达 | 相关场景使用 |
| 使用成本 | 学习、安装、维护、清洁、携带、收纳 | 目标者能力或场景相关时使用 |
| 品质与寿命 | 耐用性、使用周期、维修成本 | 高使用频率时优先 |
| 风险与信任 | 品牌、售后、退换、试错容忍度 | 高价格或高风险场景优先 |
| 关系表达 | 礼物含义、惊喜、分寸、贵重程度 | 为他人购买时优先 |
| 时间限制 | 使用日期、送达期限、是否能等待 | 存在明确事件时使用 |
| 排除项 | 不喜欢、不能用、过去踩坑 | 存在不确定方向时优先 |

#### 核心完成条件

需求卡片不要求填满候选需求池。形成卡片前至少需要：

- 一个明确的购买目标。
- 预算或对价格的态度。
- 主要使用情境。
- 已知的硬性限制或排除项。
- 至少一个优先级或取舍方向。

#### 候选项呈现规则

- 每轮最多展示 3–4 个高相关候选项。
- 始终提供“其他”和“不确定”。
- 候选项必须来自当前角色轮廓和购买场景。
- 不展示完整问卷，不要求用户逐项填写。
- 用户已经表达的信息不得再次作为问题提出。

### 5.3 第三层：目标认知补全

第三层不是继续扩充人物属性，而是判断消费者对目标者的理解是否存在会改变购买方向的认知缺口。

#### 重点识别的缺口

- 消费者使用性格概括代替了实际行为。
- 消费者不知道目标者当前使用什么或哪里不满意。
- 目标者存在没有被提到的明确排斥项。
- 目标者可能缺少使用某类产品的时间、空间、经验或能力。
- 消费者的判断主要来自自己的推测，而不是目标者表达或实际观察。
- 目标者还有共同使用者或环境条件没有被考虑。
- 消费者的购买期待与目标者的实际习惯可能冲突。

#### 可使用的追问方式

| 方式 | 示例 |
| --- | --- |
| 行为证据 | “你最近看到他在哪些事情上花时间最多？” |
| 过去事件 | “上一次给他买类似东西时，他后来真的使用了吗？” |
| 排除问题 | “有什么东西你觉得他一定不会用？” |
| 判断依据 | “你为什么觉得他更看重实用而不是外观？” |
| 反事实 | “如果操作稍复杂但效果更好，他会愿意学习吗？” |
| 强制取舍 | “如果只能保留方便和品质中的一个，他更可能选哪个？” |

系统每次只追问一个最高影响缺口。无法在合理轮次内解决的信息保留为待确认项，不能由模型自行补全为事实。

## 6. 对话策略

### 6.1 默认节奏

目标是在 3–5 次用户回复内形成卡片。

```text
用户表达模糊需求
        ↓
第 1 轮：识别目标者、购买场景和主要使用者
        ↓
第 2 轮：补齐关系和关键角色
        ↓
第 3 轮：提出 3–4 个高相关候选直接需求
        ↓
第 4 轮：追问一个最高影响的目标认知缺口
        ↓
第 5 轮：解决主要冲突并确认需求卡片
```

轮次是上限目标，不是固定脚本。信息已经存在时应跳过对应问题；不存在高影响认知缺口时可以提前形成卡片。

### 6.2 问题选择

系统每轮从未确认信息中选择价值最高的一项：

> 提问价值 = 对后续选择的影响 × 当前不确定程度 × 消费者能够回答的概率 ÷ 回答成本

满足以下任一条件的问题通常值得提出：

- 不同答案会改变可能的品类方向。
- 不同答案会改变预算或价值取向。
- 答案可能产生新的硬性排除条件。
- 当前判断可能建立在消费者未经验证的推测上。

### 6.3 停止条件

同时满足以下条件时停止追问：

- 第一层外轮廓已经形成。
- 第二层核心字段足以支持后续推荐。
- 没有仍值得占用一轮对话的高影响认知缺口。
- 用户能够确认或修正当前需求卡片。

低影响或消费者无法回答的信息作为待确认项保留，不延长对话。

## 7. 需求卡片设计

### 7.1 用户可见内容

```text
需求卡片

这次想解决什么
- 购买目标
- 使用或赠送场景

为谁购买
- 目标身份
- 你与目标者的关系
- 谁购买 / 谁决定 / 谁使用

已经明确的需求
- 预算与弹性
- 使用情境
- 重要偏好
- 硬性限制与排除项
- 优先级与必要取舍

还需要确认
- 可能影响选择、但目前无法确定的事项
```

卡片不展示需求的推理过程、形成说明、信息来源、置信度或内部状态。

### 7.2 用户编辑规则

- 用户可以直接编辑、删除或补充字段。
- 用户修改后，以最新内容为准，不保留冲突的旧结论。
- 删除一个关键字段后，系统只在该字段会阻断后续推荐时继续追问。
- “还需要确认”中的项目可以由用户回答，也可以保留到后续阶段。

### 7.3 模型内部状态

模型可以为每个字段维护以下不可见信息：

- 信息来自用户明确表达、消费者推测还是模型待确认假设。
- 当前是已确认、待确认还是未知。
- 置信程度。
- 最近一次更新所在的对话轮次。

这些状态只用于选择下一问题、解决信息冲突和处理用户修正，不属于用户界面或需求卡片的交付内容。

## 8. 页面与交互设计

### 8.1 开始页

```text
┌──────────────────────────────────────────────────────┐
│ AI Shopping Guide                                    │
│                                                      │
│ 先帮你把需求想清楚                                    │
│ 不用知道商品名称，告诉我你想为谁解决什么问题。          │
│                                                      │
│ ┌──────────────────────────────────────────────────┐ │
│ │ 例如：想给刚退休的爸爸买件东西，但没想好买什么…… │ │
│ └──────────────────────────────────────────────────┘ │
│                                      [开始梳理需求]   │
└──────────────────────────────────────────────────────┘
```

规则：

- 用户可以只描述对象、场景或模糊目标。
- 空输入时主按钮不可用。
- 首屏不要求用户先选择商品品类。

### 8.2 轮廓形成

```text
┌──────────────────────────────────────────────────────┐
│ AI：这件东西主要是送给爸爸，由他自己使用吗？           │
│ 这会帮助我区分谁使用、谁决定。                         │
│                                                      │
│ [是，他自己用] [我们一起用] [还不确定] [其他情况]      │
│                                                      │
│ 你也可以直接补充：________________________            │
└──────────────────────────────────────────────────────┘
```

- 每轮只处理一个主题。
- 用一句短说明解释问题与购买决定的关系。
- 用户初始表达已经明确的信息直接写入轮廓，不再次确认。

### 8.3 候选直接需求

```text
┌──────────────────────────────────────────────────────┐
│ 根据你对爸爸的描述，下面哪些最重要？最多选两项。        │
│                                                      │
│ [日常确实用得上] [操作简单] [有纪念意义] [品质耐用]     │
│ [其他] [我还不确定]                                  │
└──────────────────────────────────────────────────────┘
```

- 候选项是需要确认的方向，不是模型结论。
- 选项随关系、角色和场景变化。
- 不因“退休”“父亲”等标签默认推断健康、审美或技术能力。

### 8.4 认知缺口追问

```text
┌──────────────────────────────────────────────────────┐
│ 你提到希望“日常用得上”。他最近最常主动花时间做什么？   │
│                                                      │
│ [运动] [阅读] [做饭] [和家人联系] [自己填写]           │
│ [我其实不太确定]                                     │
└──────────────────────────────────────────────────────┘
```

- 问题优先要求行为或事件信息，不要求用户给目标者贴标签。
- 用户选择“不确定”后，不用相同方式重复追问。
- 如果答案不会改变需求卡片，则不提出该问题。

### 8.5 需求卡片确认

```text
┌──────────────────────────────────────────────────────┐
│ 需求卡片                                      [编辑] │
│                                                      │
│ 这次想解决什么                                       │
│ 给刚退休的爸爸准备一件日常会使用的礼物                 │
│                                                      │
│ 为谁购买                                             │
│ 爸爸；你负责购买和付款；爸爸是接收者和使用者            │
│                                                      │
│ 已经明确的需求                                       │
│ • 预算约 ¥2,000                                     │
│ • 优先日常实用和操作简单                              │
│ • 不希望只是摆设                                     │
│                                                      │
│ 还需要确认                                           │
│ • 他最近最愿意长期投入的兴趣方向                       │
│                                                      │
│                              [确认需求] [继续补充]     │
└──────────────────────────────────────────────────────┘
```

卡片只展示当前需求内容。模型如何形成字段以及对字段的置信程度不在界面中呈现。

### 8.6 移动端

- 对话为主视图，当前轮廓以顶部折叠摘要呈现。
- 候选项可以自动换行，不使用横向滚动。
- 需求卡片按四个区块纵向排列。
- 底部固定当前主操作：“回答”“查看需求卡片”或“确认需求”。

## 9. 关键状态

| 状态 | 体验要求 |
| --- | --- |
| 初始信息很少 | 从目标者或场景中选择一个最高价值问题 |
| 自用场景 | 自动合并消费者与目标者相关角色 |
| 多人使用 | 记录主要目标者与共同使用者，识别冲突约束 |
| 用户不确定 | 允许回答“不确定”，必要时写入待确认项 |
| 角色信息冲突 | 用一次确认问题澄清，不静默覆盖 |
| 需求目标冲突 | 让用户选择优先级，或在卡片中保留未决取舍 |
| 达到轮次目标 | 生成当前卡片，不为低影响缺口继续追问 |
| 用户修改卡片 | 使用新值更新内部状态，废止冲突旧判断 |
| 生成失败 | 保留已收集信息并允许重试，不要求重新开始 |

## 10. 功能需求与验收标准

### FR-01 模糊表达启动

**验收标准**：用户只说明购买对象或模糊场景时，系统进入需求理解流程，不直接推荐商品。

### FR-02 两轮形成目标角色轮廓

**验收标准**：信息允许时，系统在前两次用户回复后识别目标身份、消费者与目标者的关系，以及主要购买角色；已知信息不重复询问。

### FR-03 动态候选直接需求

**验收标准**：系统每轮最多提供 3–4 个与当前轮廓相关的候选项，并提供“其他”和“不确定”；不展示固定完整问卷。

### FR-04 高影响认知缺口

**验收标准**：系统只在答案可能改变购买方向时追问目标认知缺口；问题优先基于行为、事件或排除项，而不是要求用户概括性格。

### FR-05 合理停止

**验收标准**：核心信息足够且不存在高影响缺口时，系统在 3–5 次用户回复内生成需求卡片；低影响未知信息不能阻止生成。

### FR-06 用户可见需求卡片

**验收标准**：卡片包含购买目标、目标角色轮廓、已明确的直接需求和必要的待确认项；不显示推理过程、形成说明、信息来源或置信度。

### FR-07 卡片修改

**验收标准**：用户可以修改、删除或补充字段；修改后使用最新值，并删除或更新与其冲突的旧内容。

### FR-08 下游交付

**验收标准**：确认后的卡片能够提供目标角色、购买目标、预算、使用情境、优先级、约束、排除项和待确认项，不依赖完整对话文本也能被后续推荐能力使用。

## 11. AI 行为规则

1. 先读取用户已经表达的信息，再决定缺少什么。
2. 第一层只形成购买相关的粗粒度轮廓，不扩展为长期人物画像。
3. 不根据年龄、性别、职业或家庭角色直接推断消费偏好。
4. 每轮只询问一个主题，候选项不超过四个。
5. 只询问答案可能改变后续选择的问题。
6. 优先询问实际行为、过去事件和排除项，谨慎使用抽象性格判断。
7. 消费者的判断可以作为待确认假设，不能自动转化为目标者事实。
8. 用户回答“不确定”后，降低同类问题优先级，不重复施压。
9. 在 3–5 次用户回复内优先形成可用卡片，低影响缺口留待后续。
10. 用户卡片不展示内部推理、来源、形成说明和置信度。

## 12. 原型测试

### 主任务：为他人购买

> 你想给刚退休的爸爸买件东西，预算大约 2000 元，但还没有想好买什么。请使用产品把需求梳理清楚。

观察：

- 前两轮是否形成正确的身份、关系和角色组成。
- 候选直接需求是否与当前人物和场景相关。
- 第三层问题是否帮助用户想到此前遗漏的信息。
- 用户是否觉得问题过多、重复或无法回答。
- 最终卡片是否准确，用户是否愿意修改错误字段。

### 补充任务：自用

> 你想改善在家办公时总是腰酸的问题，但还不知道应该买什么。请使用产品把需求梳理清楚。

观察：

- 系统是否自动识别消费者与目标者为同一人。
- 是否避免逐项询问已经重合的购买角色。
- 第三层是否能从实际使用行为中发现遗漏，而不是强行构造人物画像。

### 结束访谈问题

1. 哪个问题帮助你意识到自己之前没有说明的需求？
2. 哪个问题没有必要或很难回答？

## 13. 进入下一阶段的条件

本设计先进入低保真或可点击原型测试。只有当用户能够在可接受的轮次内形成准确、有新增价值且能被下游使用的需求卡片后，才进入研发实现；商品推荐和选购方案仍作为独立后续功能处理。
