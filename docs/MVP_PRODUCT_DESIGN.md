## 2. 本轮目标

让一个只有模糊消费意图的用户，在一次会话中完成三件事：

1. 看清自己的目标、约束和优先级。
2. 理解不能同时满足的目标以及必要取舍。
3. 获得一份可直接开始选购的品类、规格和预算方案。

MVP 的验证重点是“用户是否更会做决定”，不是“AI 是否能罗列商品”。

## 3. 目标用户与触发场景

### 核心用户

缺少品类知识、没有形成明确选择标准，但愿意说明使用场景和现实约束的普通消费者。

### 典型触发

- 用户只知道想改善的生活场景，不知道该买什么。
- 用户同时在意预算、体验、耐用性或空间，但不知道如何排序。
- 用户查过一些商品，却无法把参数与自己的需求对应起来。

### 非目标用户

- 已经知道品牌、型号，只需要查价或下单的用户。
- 需要企业采购审批、供应商管理或大宗履约的用户。
- 需要产品替其完成高风险、不可解释决策的用户。

## 4. MVP 范围

### P0：原型必须覆盖

| 能力 | 用户价值 |
| --- | --- |
| 模糊意图输入 | 用自己的话开始，不要求先懂品类术语 |
| 渐进式澄清 | 只补充会影响方案的关键信息 |
| 需求卡片 | 随时查看、确认和修改系统理解 |
| 冲突与取舍提示 | 知道哪些目标无法同时最大化 |
| 1–3 个差异化方案 | 按不同优先级选择路径，而非浏览长列表 |
| 方案解释 | 将每条建议连接到用户目标或约束 |
| 条件修改与方案更新 | 新信息出现后可修正，不被早期答案锁定 |
| 选购检查清单 | 把方案带到下一步搜索或实际购买 |

### P1：验证通过后考虑

- 保存、复制或分享选购方案。
- 根据用户反馈调整方案排序。
- 跨会话恢复未完成的决策。

### 本轮不做

- 实时商品、库存、价格和购买链接。
- 登录、长期用户画像和跨场景记忆。
- 商品广告、佣金排序和交易履约。
- 多人共同决策与商家端功能。
- 语音、图片识别和多模态输入。

## 5. 核心用户流程

```text
表达模糊意图
      ↓
识别已知信息与最大不确定项
      ↓
逐轮澄清 ──────────────┐
      ↓                 │
查看 / 修改需求卡片 ────┘
      ↓
确认首要目标与必要取舍
      ↓
生成 1–3 个差异化选购方案
      ↓
比较并选择方向
      ↓
修改条件 → 更新受影响的方案
      ↓
获得选购检查清单
```

### 进入方案生成的条件

系统至少知道：

- 要改善的场景或完成的任务。
- 使用对象与关键环境。
- 预算上限或预算弹性。
- 至少一个首要目标。
- 已发现的硬约束。

用户仍不确定的字段可以标记为“待定”，不能用虚构信息补齐。

## 6. 信息模型

### 6.1 需求卡片

| 字段 | 示例 | 交互规则 |
| --- | --- | --- |
| 要解决的问题 | 长时间在小空间办公不舒服 | 一句话，可编辑 |
| 使用对象 | 成年人，每周 5 天 | 可选标签 + 自定义 |
| 环境 | 约 3㎡、不能打孔 | 硬约束突出显示 |
| 预算 | 总预算 3000 元，可浮动 10% | 区分上限与期望值 |
| 首要目标 | 舒适、节省空间 | 最多 2 项并排序 |
| 次要目标 | 外观统一 | 可被取舍 |
| 已知偏好 | 不要复杂安装 | 可编辑 |
| 待确认 | 是否需要视频会议设备 | 不确定信息显式保留 |

### 6.2 方案卡片

每个方案固定包含：

1. **一句话定位**：这个方案优先解决什么。
2. **适合你的原因**：逐条对应需求卡片，不用通用宣传语。
3. **购买组合**：品类、作用、预算区间、关键规格。
4. **主要取舍**：得到什么、放弃什么。
5. **不适用条件**：出现什么情况时不要选。
6. **下一步清单**：可复制的搜索条件与现场检查项。

## 7. 页面与交互设计

### 7.1 开始页

```text
┌──────────────────────────────────────────────────────┐
│ AI Shopping Guide                                    │
│                                                      │
│ 先想清楚，再开始买                                    │
│ 描述你想改善的场景，不需要先知道商品名称。              │
│                                                      │
│ ┌──────────────────────────────────────────────────┐ │
│ │ 例如：我想把家里的小角落改得适合长期办公……         │ │
│ └──────────────────────────────────────────────────┘ │
│                                      [开始梳理需求]   │
│                                                      │
│ 可选示例：送礼 / 换季装备 / 小空间改造                 │
└──────────────────────────────────────────────────────┘
```

规则：

- 主输入支持自然语言，空输入时按钮不可用。
- 示例用于降低启动成本，点击后只填入输入框，不直接提交。
- 首屏不展示商品或要求选择品类。

### 7.2 澄清页

```text
┌──────────────────────────────┬───────────────────────┐
│ 对话                         │ 你的需求               │
│                              │                       │
│ AI：这个空间大约有多大？      │ 目标：长期办公更舒适    │
│ 这会影响桌椅和收纳的选择。     │ 预算：≤ ¥3,000         │
│                              │ 环境：小空间            │
│ [约 3㎡] [不确定] [自己填写]   │ 首要：舒适 / 省空间     │
│                              │                       │
│ 你：约 3㎡，而且不能打孔。      │ 待确认：使用频率        │
│                              │             [编辑]    │
│ ┌──────────────────────────┐ │                       │
│ │ 输入补充信息……            │ │                       │
│ └──────────────────────────┘ │                       │
└──────────────────────────────┴───────────────────────┘
```

规则：

- 每次只问一个主题，并用一句话说明为什么要问。
- 优先提供可跳过的快捷选项，同时允许自由输入。
- 新信息写入需求卡片时短暂高亮；AI 的推断必须标记“请确认”。
- 用户直接编辑卡片后，对话区说明哪些判断会受影响。
- 达到生成条件后展示“看看方案”；用户也可继续补充。

### 7.3 取舍确认

当两个目标明显冲突时，在生成方案前用一次轻量确认：

```text
在当前预算与空间下，舒适度和“尽量不占空间”不能同时最大化。

你更愿意：
(●) 保留更舒适的座椅，接受桌面稍小
( ) 保留更大的桌面，接受座椅调节较少
( ) 我还不确定，让我看两个方案
```

用户选择“不确定”时，系统应把冲突转化为两个方案，而不是继续追问。

### 7.4 方案页

```text
┌──────────────────────────────────────────────────────┐
│ 你的选购方案                     [修改需求] [复制清单] │
│                                                      │
│ [推荐] 舒适优先                    预计 ¥2,500–3,000   │
│ 把预算集中在可调座椅与合适桌高，收纳保持轻量。          │
│                                                      │
│ 购买组合                                             │
│ 座椅 ¥1,400–1,800 | 桌子 ¥800–900 | 照明约 ¥300      │
│                                                      │
│ 为什么适合你                                         │
│ ✓ 每周使用 5 天 → 优先长期舒适                        │
│ ✓ 约 3㎡ → 控制桌深与收纳体积                         │
│                                                      │
│ 取舍：桌面面积较小；不适合需要双屏并排的情况            │
├──────────────────────────────────────────────────────┤
│ [替代] 空间优先                                      │
│ 用可折叠桌释放空间，但牺牲部分稳定性和随时可用性。       │
├──────────────────────────────────────────────────────┤
│ 有什么需要改变？ [预算] [空间] [优先级] [其他]          │
└──────────────────────────────────────────────────────┘
```

规则：

- 默认展开推荐方案，替代方案显示明确的差异摘要。
- 预算总和与分项保持一致；无法确定时使用区间并说明弹性来源。
- 每个推荐理由必须能追溯到需求卡片字段。
- 条件变化后，仅更新受影响内容，并以“变化说明”告知用户。
- 不使用“完美、最佳、一定适合”等无法证明的措辞。

### 7.5 移动端

- 对话为主视图，需求卡片收纳为顶部可展开摘要。
- 方案按纵向卡片呈现，不使用需要横向滚动的对比表。
- 底部固定当前主要操作：“回答问题”“查看方案”或“复制清单”。

## 8. 关键状态

| 状态 | 体验要求 |
| --- | --- |
| 初始空状态 | 给出场景示例，不预设品类 |
| AI 思考中 | 显示当前任务，如“正在整理预算与优先级”，允许停止 |
| 信息不足 | 明确缺少的决策变量，只追问最高影响项 |
| 用户不确定 | 记录为待定；能用分支方案表达时不阻断 |
| 条件冲突 | 指出冲突来自哪些条件，提供排序或双方案选择 |
| 超出预算 | 给出需减少的品类/规格或预算弹性，不静默超支 |
| 无法形成可靠方案 | 说明缺少什么，并提供继续补充或带走现有摘要 |
| 生成失败 | 保留已确认需求，允许重试，不要求重新开始 |
| 修改后更新 | 标记新增、删除和改变的建议及原因 |

## 9. 核心功能需求与验收标准

### FR-01 模糊意图启动

**验收标准**：给定用户只输入场景目标、没有品类名时，系统进入澄清流程，不直接返回商品列表。

### FR-02 决策相关追问

**验收标准**：每轮最多询问一个主题；问题附带简短原因；用户可回答“不确定”或跳过。

### FR-03 需求可见与可改

**验收标准**：用户能查看系统当前理解；修改任何字段后，新值立即显示，并在后续方案中生效。

### FR-04 取舍处理

**验收标准**：当两个目标不能同时满足时，系统指出冲突并让用户排序；用户不排序时，可以用差异化方案表达两条路径。

### FR-05 方案生成

**验收标准**：每个方案包含定位、购买组合、预算、选择标准、匹配理由、取舍、不适用条件和下一步清单；最多三个方案。

### FR-06 方案可解释

**验收标准**：每条“适合你的原因”都能对应一个已确认的用户目标或约束；未确认的推断不能作为确定事实。

### FR-07 动态更新

**验收标准**：用户修改预算、环境或优先级后，系统保留未受影响的信息，更新方案并说明变化原因。

### FR-08 选购清单

**验收标准**：用户可获得按品类组织的预算区间、关键规格、避坑项和检查项；内容不依赖站内购买链接也可使用。

## 10. AI 产品规则

1. 先识别“还缺什么会改变决策”，再决定是否追问。
2. 区分用户明确表达、用户确认和系统推断，不混写为事实。
3. 不因掌握一个品类线索就提前收敛；先检查是否存在替代品类或组合方式。
4. 只有存在实质性取舍时才生成多个方案。
5. 解释使用“需求/约束 → 选择 → 结果”的因果结构。
6. 用户修正信息后，以最新确认内容为准，并废止冲突的旧判断。
7. 在缺乏商品数据时不编造品牌、型号、实时价格、库存或优惠。

## 11. 原型测试任务

### 主任务

> 你在家里有一个约 3㎡ 的角落，每周需要办公 5 天。现在总预算大约 3000 元，希望坐得舒服，但也不想让房间显得拥挤。请使用产品形成一个可以开始购买的方案。

### 观察点

- 用户是否理解为什么被问这些问题。
- 用户能否发现并修正需求卡片中的误解。
- 用户是否理解“舒适优先”和“空间优先”的差异。
- 用户能否根据方案说出先买什么、预算如何分配、检查什么。
- 用户修改预算后，是否理解方案发生了哪些变化。

### 结束访谈问题

1. 现在你对自己要解决的问题是否比开始时更清楚？为什么？
2. 哪个问题有帮助，哪个问题不值得回答？
3. 你会选择哪个方案？请说出它的主要取舍。
4. 还缺少什么信息，你才会真正开始购买？

## 12. 评审与下一步

本设计适合进入低保真可点击原型，不适合直接作为完整研发范围。下一步应先完成 5–8 人原型测试，按 `PRODUCT_HYPOTHESES_AND_DECISIONS.md` 的门槛决定继续、修改或停止。
